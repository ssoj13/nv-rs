## Workspace boundaries

The root Cargo workspace contains `crates/*` and `xtask`. `device/` and `python/` are excluded and have separate build requirements. A successful root workspace check does not validate them. `device/` patches the NVIDIA `cuda-rust` crates to the `ssoj13/cuda-rust_b` fork (`[patch."https://github.com/NVIDIA/cuda-rust.git"]` in `device/Cargo.toml`) so its graph holds one `cuda-core`; the root workspace stays on NVIDIA upstream, and the fork must be refreshed if the root adopts an NVIDIA-only `cuda-core` API.

## Dataflow

```text
SDK headers + LibSpec in each sys build.rs
  -> nv-bindgen::generate (vcv-rs discovery, bindgen, shims, inventory)
  -> OUT_DIR generated types/API/shims
  -> *-sys crate -> Rust wrapper -> application / Python extension
                         |
                         +-> cuda-core contexts, streams, device buffers

runtime DllSpec (nv_loader::catalog) -> nv-loader::candidates -> open_first -> open_library
  -> cached API / cached LoadError -> native entry point / typed failure

wgpu Vulkan or DX12 allocation
  -> exported OS handle -> cuda-core-ext import
  -> nv-wgpu shared resource + timeline semaphore -> CUDA / graphics work
```

## Traps and verification

- Inspect each crate's Cargo `[lib].path`; entry points commonly use names such as `nv_loader.rs`, not `lib.rs`.
- Configure runtime search directories before the first sys call. The loader macros cache both success and failure in `OnceLock<Result<...>>`; later search-directory additions do not retry a failed initialization.
- Generated output belongs in `OUT_DIR`; change `LibSpec`, generator logic, or loader macros rather than patching generated files.
- NGX uses static linking; prebuilt Rust bindings do not supply its native libraries (`nvngx_dlss.dll` / `nvngx_dlssd.dll`). `crates/nv-demo/build.rs` stages both DLLs alongside the binary when present in `.sdk/ngx/`.
- `nv-demo` `LaunchParams` (`renderer.rs`) and `Params` (`raytracer.cu`) share a strict **640-byte** C ABI (`csg_prev_xforms` at offset `592`, `sdg_ray_count` at offset `632`) checked by compile-time Rust `assert!` and CUDA `static_assert`; keep both definitions synchronized when adding launch fields.
- **Audit traps (`plan1.md`, 2026-11-23, all fixed in `02c1cd9`; kept as regression hints)**: watch for `rr_last_exposure = f32::NAN` sentinel comparisons (`main.rs`), `ias_state` checking `sat_angle`/`fractal_transform` when `!show_classic` (`renderer.rs`), `Accel::custom` inheriting `compact: true` (~246 serial GPU stalls per scene switch), `RoadTerrainTile` Tier 3B missing `t_box_in` guard (`csg_eval.cuh`), `SaveJpeg` resetting `accum_count` when `max_accum == 0` (`renderer.rs`), and `CursorGrabController` missing one-shot `CursorGrab(Locked)` on frame 0 (`main.rs`).

- **Workspace audit traps (`plan2.md`, 2026-11-23)**: `cuda-core` frees a dropped buffer without waiting for GPU work and requires raw-pointer users to hold an access lease (`allocation.rs:94-126`). Measured on GPU: a stream-ordered buffer (`DeviceBuffer::uninitialized_async`) dropped while work on a *different* stream still writes it is reused and corrupted 20/20 (`crates/curand/tests/lease.rs`; 10/10 from Python, `python/nv-py/tests/test_lease.py`), while same-stream and synchronous (`zeroed`, `from_host`) buffers were not; `cuda_core_ext::lease::enqueue_leased` is the fix helper. Fixed and gated in Waves 1-2 (kept as regression hints): `cublas::Handle::set_stream` skipped `bind_to_thread` on a stream-cache hit; `cufft::Plan` was auto-`Sync`; `optix::InstanceBuffer` reused one pinned staging buffer without a fence; `nv-wgpu` `InteropSemaphore` destroyed the Vulkan semaphore before its CUDA import dropped. Fixed in Wave 5 (gated): `nv-bindgen` no longer falls back to prebuilt bindings on a generator error or panic (fallback only for `NV_RS_USE_PREBUILT=1`, an absent SDK, or an unloadable libclang; header drift is warned and the fallback is not sticky); the build-time SDK directory hint in `DllSpec` exists only in debug builds; runtime library specs live once in `nv_loader::catalog` (sys crates, `diag::probe_all`, NPP) and loaded libraries are version-gated against the bound major version where a version query exists.
- `nv-demo` camera navigation comes from `camera-rs` (`camera` umbrella crate, git `main`, features `egui` + `serde`); the vendored `camera_core` / `camera_egui` copy was removed on 2026-11-23. nv-demo-only flight feel (wheel step `1.25`, floor `0.1`, progressive Shift ramp, cursor lock on drags) is opted in once through `CameraDriver::set_nav_extras` (`main.rs`); change camera behaviour in `camera-rs`, never by copying its sources back. `altitude_speed_multiplier` is nv-demo host policy and lives in `ui.rs`.
- **Wrapper contracts after `plan2.md` Waves 1-2 and 1b (gated on RTX 3080 Ti)**: a workspace/scratch pointer given to a native library is owned by the handle or descriptor that uses it (`cublas::Handle`, `cusparse` SpSV/SpSM/SpGEMM, `cublasLt` `MatmulDesc`); raw attribute setters that can change what a native call reads or writes are `unsafe fn`; every handle binds its CUDA context on each entry and in `Drop`; `cufft::Plan` and `nccl::GroupGuard` are deliberately `!Sync` / `!Send`; contexts are compared by value (`cuda_core_ext::same_context`) and streams by native handle + context (`same_stream`), never by `Arc::ptr_eq` (`default_stream()` returns a fresh `Arc`, and two `Context::new(0)` handles are one primary context); teardown failures go to the typed, bounded sink `cuda_core_ext::teardown` (library, operation, real native code; drain with `teardown::take`), never into `CUDA_ERROR_UNKNOWN` of the next call; scratch memory is one implementation, `cuda_core_ext::scratch::Scratch` (`cublas`, `cudnn`, `cusolver`, `cusparse`, `nvcomp`; `cufft` wraps it; `optix::Scratch` is separate); caller buffers that may be stream-ordered and cross streams go through `cuda_core_ext::lease::enqueue_leased` (today: `curand`, and every `python/nv-py` binding via `buf_util::enqueue_leased`); `nv-wgpu` records all raw Vulkan work into a wgpu encoder and submits through `wgpu::Queue::submit` (no private queue, no raw `vkQueueSubmit`); `optix` instance structures require children built on the IAS build stream; NGX calls are serialised by one process-wide mutex; a test that asserts a hazard must be backed by a hardware reproduction (three such tests were removed or inverted after the hardware disagreed).
- cuDNN next to another cuDNN 9 in the same process (e.g. PyTorch's, Windows): `cudnn-sys` adopts the already-loaded copy (its directory, version-gated, loader diag `cudnn`/`adopt`) and rejects a different copy; a second build cannot share a Windows process. The reverse order cannot be prevented from Rust: if nv-rs loads cuDNN first, a later `import torch` can fail with `WinError 127`, so import torch first (`python/nv-py/tests/conftest.py` does).
- Preserve CUDA context ownership and stream ordering when changing wrappers. Keep parent objects alive until dependent native objects and queued operations are finished.

Run `cargo clippy --workspace --all-targets` and `cargo test --workspace` for host changes. Inspect full diagnostics before suppressing warnings. Scope extra checks to the affected excluded workspace when relevant.
