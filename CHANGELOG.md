## [Unreleased]

### Added
- **`nv-demo` object axes overlay** (`OVERLAY:NEXT`): GPU provider `ovl_axes` reads the device CSG instance and compound records and appends X / Y / Z axis segments (red / green / blue, constant 40 px, screen-constant width, faded + dashed where occluded) per qualifying instance; skips invisible, mask-0, unbounded and crowd-bone instances; honours the shared filter (scope selected / radius, frustum + screen-size cull); selected instances get the SELECTED flag and their oriented bounds. Icon toggle and axis length in the viewport toolbar (persisted). Cost on `gundo` `road_cruise` (1216x936, 4 spp, 6 bounces, DLSS-RR off (the overlay is not drawn while DLSS-RR owns the display)): frame work median 99.38 -> 99.28 ms.
- **`nv-demo` GPU picking and selection**: the primary launch writes a 32 B pick record for the clicked pixel (async readback, consumed the next frame); click selects, Shift+click toggles, empty space clears, Ctrl+click / double click / Pick mode possess (model shared with warpbro-rs / squarebob-rs through `sl-config`). The selection drives the overlay Selected scope and the axes highlight. `LaunchParams` grows to 656 B (`pick_px` reuses the pad word, `pick_record` appended).
- **`nv-demo` IS counters and `--bench-views`** (`P37:SWEEPS` (1)): per hit group intersection-program invocations and traced rays behind `--is-counters` / a Flight stats toggle (zero cost when off: one uniform branch), and a fixed camera set benchmark `--bench-views p37 --out <csv>` (RT ms median / min / p95 and IS counts per view). First run (832x640, 4 spp, 6 bounces), RT ms median / IS total per frame: osm_beach_bookmark 120.6 ms / 9.0 M, osm_refinery 201.4 / 10.8 M, osm_street_grazing 310.2 / 22.5 M, osm_topdown 34.1 / 9.1 M, marina_street 396.3 / 20.3 M, marina_grazing 269.5 / 16.9 M; IS counts are identical between two runs (saved config, DLSS-RR on).
- **`nv-demo` viewport category filter** (toolbar eye dropdown): semantic groups (Humans, Animals, Vehicles, Buildings, Roads, Street furniture, Industrial, Water, Ground, Unknown) with per-class sub-rows; a `u64` `hidden_semantics` mask is rejected in every CSG intersection program through `csg_instance_semantic`, so hidden classes vanish from camera, bounce and shadow rays; classic instances use the same rule on the host. `LaunchParams` is now 672 B. Vegetation / Terrain features (csg-rs P41) and OSM classes (P42) are shown disabled with their status.
- **`nv-demo` display modes (`DEMO:VIEWS`)**: viewport selector CSG / Wireframe (persisted, with a line-width slider). Wireframe: native viewport resolution (DLSS and render scale off), one primary ray per pixel, GPU marching-squares contours on the pixel lattice with corner-preserving Laplacian smoothing, flat light-grey faces with slight ray-traced AO. `gundo` 1216x936: RT 9.3 ms. Voxel view is pending until csg-scene exposes a voxel volume / ESDF.
- **`nv-demo` overlay renderer** (`overlay.rs`): one GPU-first line renderer for every overlay. Providers (`OverlayProvider::emit`) fill a reused list; GPU providers append 64-byte `OverlaySegmentPod` / `NvOverlaySegment` records (contract header `shaders/overlay_segment.cuh`, asserted on both sides) to a device buffer with an atomic counter; one raster pass draws antialiased constant-width strokes (kind dispatch, world projection, dashes, depth test, line LOD fade by projected feature size) and one composite stabilises the coverage temporally (motion-reprojected, clamped, blended) and blends it in linear light into the display targets, so captures include it. Typed device faults (overflow, unprojectable, unsupported kind) are read back asynchronously and reported. Shared persisted filter with icon toggles (kinds, scope all / selected / radius, min screen px, temporal, in captures). The wireframe contours are its first provider. Cost on `gundo` `grand_tour` (1216x936): +0.28 ms in the tonemap section; far-region flicker (second temporal difference) 9.08 -> 5.44 with LOD fade + temporal stabilisation. `nv-demo --bench-rail ... --png-dir <dir>` writes every frame's displayed image for temporal A/B.
- **`nv-demo` viewport toolbars**: the viewport toolbar is left-aligned; the possession toolbar (mounts, Level, Eject, Pick, Possess Car, Pin) is always present, stacked on the inner side of the viewport toolbar in the same corner, collapsed while not possessing, auto-expanded on entering possession unless the user collapsed it, collapsed on leaving unless pinned (choices persist). Both toolbars share one style (icon-only `egui-phosphor` buttons of one size with the old labels as tooltips, one frame, one spacing).
- **`nv-demo` rail benchmark** (`d4f1098`): `nv-demo --bench-rail <rail> --scene <id> --out <csv> [--frames] [--warmup] [--image <pfm>]` flies one scene rail from t = 0 in lockstep with the renderer (fixed 1/60 s * time_scale steps), with frozen traffic/crowd, free Pinhole camera, UI commands dropped and the user config untouched, and exits after writing the CSV atomically. The perf CSV now records per frame `possessed, projection, eye, width, height, spp, bounces`; `--image` writes the last frame's linear colour as PFM, and the sample frame index restarts so two runs of one build are bit-identical. Earlier free-running A/B numbers did not control camera state (possession / 360 projection) and are superseded (`audit/2026-11-24/perf_rt.md`).
- **`nv-demo` Flight stats** (collapsible subsection of "Cinema & Camera Rail"): live rail time / loop, camera speed and turn rate, scene load (visible instances, LOD 0/1/2, culled, evaluation paths prim / union / exact union / RPN), RT min / median / p95 / max, histogram, five slowest rail positions (click jumps the rail), RT vs rail time with the previous loop overlaid, visible instances and LOD 0 share vs rail time, CSV export in the bench schema. Fed from the same per-frame `PerfSample` as the perf CSV; ring buffers sized once.

### Fixed
- **Workspace-wide audit repairs, Waves 1-2 (`audit/2026-11-23/plan2_full.md`; gated on RTX 3080 Ti at `05efa7e`: clippy `-D warnings` clean, 375 tests pass, ignored GPU tests of every touched crate pass)**. Every finding was re-verified against source and SDK headers before the change; refuted findings are listed in `PLAN.md` section 5.
  - **Buffer lifetime**: a stream-ordered `DeviceBuffer` freed while another stream still wrote it was reused and corrupted (measured 20/20); `curand` device generation now holds a `cuda-core` access lease through the new `cuda_core_ext::lease::enqueue_leased`.
  - **`cublas`**: the handle owns its workspace buffer while set and refuses a stream switch (`cublasSetStream` silently reset the workspace); context is bound on every `set_stream`; overlapping output batches, undersized `ld`, non-F32 grouped GEMM are rejected; `MatmulDesc` retains its `EmulationDesc`.
  - **`cufft`**: `Plan` is `!Sync`; the scratch lock is held until exec is queued; mixed NULL embeds and overlapping output batches are rejected.
  - **`cusparse` / `cusolver`**: scalar type must equal `compute_type`; SpSV / SpSM / SpGEMM own their buffers and run their phases in order on one stream; `set_csr_pointers` validates `nnz` and index/value types; Dn / Sp / cuSPARSE handles bind the context; Mg pointer arrays are length-checked.
  - **`cudnn` / `nvcomp`**: scratch budgets bound the whole allocation; plans keep their dependencies; `nvcomp` receipts are generation-checked, output ranges must not overlap, the manager validates layouts and decodes with the payload's options, and `BitcompPlan::uncompress_async` validates the 32-byte stream header before queuing work (was a CUDA 700 fault).
  - **`nvjpeg` / `npp` / `nvofa`**: decode validates against the bitstream geometry, `encode_yuv` against the requested subsampling; a second bitstream retrieve is a typed error; NPP "no operation" warnings are errors; NVOFA readback waits for the I/O streams.
  - **`nvenc` / `nvdec`**: `NV_ENC_ERR_NEED_MORE_INPUT` is `EncodeOutcome::NeedMoreInput` instead of an error (B-frames work); I/O streams are retained; parser user data no longer aliases a moved `Box`; `display_area` is set (1088 is cropped to 1080, not scaled).
  - **`cufile`**: `FileHandle::read` needs exclusive access; pins are taken before the fence can fail; a failed wait no longer flushes staging to the file.
  - **`ngx` / `cupti` / `nccl`**: NGX calls are serialised process-wide and success follows `NVSDK_NGX_SUCCEED`; CUPTI activity kinds are reference-counted per process and unsubscribe waits for running callbacks; `GroupGuard` is `!Send`.
  - **`optix`**: `InstanceBuffer` fences its pinned staging buffer between uploads; in-place denoise is untiled only; growth failure leaves the buffer empty; `instances_into` checks budget, context and build options; streams are compared by native handle; instance structures reject children built on another stream.
  - **`nv-wgpu` / `cuda-core-ext`**: semaphore teardown order; cubemap mip levels keep six faces; 2D textures import as 2D CUDA arrays and colour targets carry `CUDA_ARRAY3D_COLOR_ATTACHMENT`; mip counts, timeline values and foreign-context streams are validated.
- **Waves 3, 5, 6 (gated: root workspace clippy clean, 467 tests pass, `nv-demo` starts and renders; `python/nv-py` builds, pytest 77/82 with the remaining failures environmental or outside `python/`)**: `nv-demo` render-thread failures become `RenderEvent::Fatal`, captures read the displayed texture, corrupt config files are never overwritten, MP4 output is atomic, SDG depth/motion are defined for all four sensor projections; `nv-bindgen` no longer falls back to prebuilt bindings on a generator failure; `xtask stage-dlls` fails when a requested library is missing; `python/nv-py` validates DLPack imports and leases every buffer passed to asynchronous work; `nvrtc` `dlto()` passes `-dlto` (NVRTC 13.3 rejects `--dlto`); `cudnn-sys` refuses to load next to a different cuDNN copy already in the process instead of failing with Windows error 127.

### Changed
- Breaking (final wave): `xtask stage-dlls` reads `nv_loader::catalog::ALL` (own `SPECS` table deleted) and fails on a missing required companion; `xtask prebuilt` stages only what a `generated` manifest lists and rejects out dirs without one; `Shape::FunctionTable` has a required `probes` field; `CatalogEntry` has `companions_windows` / `companions_linux`; Linux names of `dlss` / `dlssd` are patterns; `ngx_sys::SDK_BIN` is `None` in release builds; generated NVAPI shims resolve each interface id once; `nv_wgpu::SharedSurfaceObject` removed (`cuda_surface_object` returns `cuda_core_ext::SurfaceObject`); `nvdec::{nv12_frame_bytes, p016_frame_u16s, psnr_u8}` removed (use `cuda_core_ext::media`); `cusolver` depends on `cusparse`, `nvdec` on `cuda-core-ext`.
- Breaking (Wave 1b): `Scratch::reserve(.., Option<usize>)` replaces `reserve_bytes` / `reserve_with_budget`; `nvcomp` aligned reserve is `reserve_aligned`; `cusparse` SpSV / SpSM `prepare` and SpGEMM `work_estimation` / `compute` lost the `scratch` parameter and take `&Arc<Stream>`; cuBLASLt descriptor constructors lost their `cuda` parameter; `ngx::take_teardown_error` became `take_teardown_errors`; dead `Budget` / `Unsupported` error variants removed from `nvenc`, `nvdec`, `nvofa` (except `nvofa::Error::Unsupported`).
- **`nv-wgpu`**: all raw Vulkan work (ownership barriers, `submit_vulkan_commands`) is recorded into a `wgpu` command encoder and submitted through `wgpu::Queue::submit`; drops of semaphores and shared resources wait for pending work.
- **Raw attribute setters that decide what a native call reads or writes are `unsafe fn`**: cuBLASLt `set_attribute_bytes` on `MatmulDesc`, `MatrixLayout`, `MatrixTransformDesc`, `EmulationDesc`, plus `set_epilogue` and `set_bias_batch_stride`.
- **`nv-demo` camera navigation** comes from the external `camera` crate (`camera-rs` `9109108`); nv-demo-only flight feel is opted in through `CameraDriver::set_nav_extras`.
- **`bootstrap.py` / CI** (`a246a6a`, workflows not executed yet): SDK installs are atomic and pinned (commits, SHA-256 table); CI lints and tests the whole workspace on Windows, runs `cargo deny`, and reads the toolchain from `rust-toolchain.toml`.
- `nvofa::OpticalFlowSession::set_io_streams` and `nvenc::EncodeSession::set_io_streams` take `&Arc<Stream>`; `nvenc::EncodeSession::encode_picture` returns `Result<EncodeOutcome>`; `nvdec::DecoderConfig` has `display_area`.
