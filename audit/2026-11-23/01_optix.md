## 4) Static and invariant verification performed

- Type widths: `OptixResult`, `OptixGeometryFlags`, `OptixBuildFlags` and the device-property flag enums are `c_int` on the MSVC prebuilt. That is the basis for L1/L2/L3: which `allow` covers which platform.
- `optixUtilComputeStackSizes*` and `SimplePathTracer` formulas in stack.rs compared with the header formulas: identical (`cssRG + cssCCTree + (max(depth,1)-1)*chOrMs + min(depth,1)*max(chOrMs, cssIS+cssAH)`; path tracer `cssRG + max(cssMS1, cssCH1 + max(cssMS2, cssCH2))`).
- `split_image` compared step by step with `optixUtilDenoiserSplitImage` (offset/copy formulas, upscale factors, inner-overlap rules): matches. `run_tiled` previous-output and internal-guide splitting (`upscale * overlap/tile`) matches `optixUtilDenoiserInvokeTiled`.
- `optixAccelRelocate` with `relocateInputs = NULL / 0` for `Relink::Keep`: allowed by optix_host.h:733-734 ("may be zero, preserving any references"). There is no defect there.
- Task log lifetime: optix_host.h:390-418 (input and log must stay live until all tasks finish; module destroy is illegal while a task executes). The `Shared` drop order (module first, then code/log/opts) plus the RwLock gate satisfies this.
- Callback: `forward_log` catches unwinds; every sink box stays alive until context drop; `LogFn: Send + Sync`. Sound.
- SBT: `SbtRecord` `repr(C, align(16))`, `offset_of!(data) == 32` const-asserted, runtime rejection of `align_of::<T>() > 16`, padding zeroed in `write_into`. Stride = `size_of::<SbtRecord<T>>()` is a multiple of 16. Sound.
- Instance layout: `size_of::<OptixInstance>() == 80`, a multiple of `OPTIX_INSTANCE_BYTE_ALIGNMENT`, const-asserted. `Aabb` layout asserted against `OptixAabb`; `MicromapDesc` against `OptixOpacityMicromapDesc`. Transform byte layouts asserted against the sys structs.
- Build-input pointer lifetimes: `Inputs` owns the inner `Vec`s (their heap storage does not move when the outer Vec grows) and lives across `sizes` and `optixAccelBuild`. Instance and pointer device arrays are kept in `_device` until after the build call; their stream-ordered free comes after the build. Sound.
- usize-to-u32 narrowing: every count goes through `count()` / `try_from`. The unchecked `as u32` casts (`inputs.len() as u32`, `size_of::<T>() as u32`, `max_new as usize`) are bounded by prior checks or are compile-time small. No truncation found.
- Panics reachable from public API: grep for `unwrap`, `expect`, `let _ =`, `.ok()` and indexing in src. The only hits are fixed-size array indexing and the `let _ =` in `PinnedHostStaging::drop` (A9). `let _ = count(..)?` at accel.rs:985 is a discarded validated value (harmless).
- Pinned staging race (A1): traced `copy_raw_range_to_device`. There is no event, sync or slot rotation between the host `copy_nonoverlapping` into `pinned.ptr` and the earlier queued `cuMemcpyHtoDAsync` from the same pointer.
- Budget ordering (A3): traced `scratch.reserve` (1841) before `within` (1890); `Scratch::growth` returns `bytes.saturating_sub(capacity)`, which is 0 after the reserve.
- Compaction syncs (A7): `DeviceBuffer::zeroed` in cuda-core = `malloc_sync` + memset + `stream.synchronize()`.

## 5) Risks / open seam questions for other slices

1. **nv-demo (renderer.rs:4237-4256, 1975-1990, 5112)**: A1 is masked only by the per-frame `stream.synchronize()`. If the frame fence is ever removed or made non-blocking (for example the "non-stalling" 3-slot profiler design), or if `upload_all` and `update_prefix` both run in one frame, IAS instance data gets corrupted silently. Also, `let _ = unsafe { Accel::instances_into(...) }.expect(..)` discards the `bool` (update vs rebuild). Worth checking that this is intended.
2. **nv-demo**: is `ShaderBindingTable` rebuilt on scene or variant switches? Each rebuild is 3-5 full stream syncs plus synchronous `cuMemAlloc`/`cuMemFree` (PF1). The same goes for every compacted `Accel::custom` build (A7, two syncs each). Together these may explain more of the "~246 serial GPU stalls per scene switch" trap than `compact: true` alone.
3. **nv-demo / render-rs denoiser usage**: confirm nobody uses `DenoiserOptions::tile` with in-place layers (D1), and that no `Denoiser`/`Pipeline` is dropped right after `invoke`/`launch` without a sync (D2), for example on resize (renderer.rs:3127-3144 does sync, but check the other teardown paths).
4. **cuda-core (external)**: `DeviceBuffer` drops free through `cuMemFreeAsync` on the *allocation* stream. Every OptiX structure read by a launch on a different stream depends on the caller's ordering (it is in the `unsafe` contracts). Check whether the cuda-core `enqueue_access` / `shared_access_writes` tracking is meant to cover cross-stream reads; the optix crate does not use it.
5. **optix-sys**: the Linux prebuilt or generated bindings make the enums `c_uint`, so L1/L2/L3 behave differently per OS. Run clippy on both OSes before converting the allows to `expect`.
6. **nv-wgpu / interop slices**: the A10 Arc-identity rule means a caller that wraps the same CUstream in two `Arc<Stream>` (for example the interop stream and a render stream) gets false "different stream" errors from `Scratch`, `InstanceBuffer` and `Denoiser`.
7. **OptiX driver behaviour (needs hardware)**: (a) whether `optixDenoiserDestroy`/`optixPipelineDestroy` with queued GPU work is safe (D2); (b) whether the destroy calls need the CUDA context current (X2); (c) whether the explicit-mode CLAS handle array is really left untouched (cluster.rs:726-729 relies on an observation on OptiX 9.1 / sm_86).
