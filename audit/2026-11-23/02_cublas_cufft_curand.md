## 5) Risks / open seam questions for other slices

1. **Allocation leases (SEAM-01) are repo-wide.** Grep shows only `crates/cupti/src/activity.rs` and `crates/cuda-core-ext/tests/interop.rs` touch `acquire`/`retain_until_complete`. Every wrapper slice (cuDNN, NPP, nvJPEG, OptiX, nvcomp, cuSPARSE/cuSOLVER, NVENC/NVDEC, nv-wgpu) that takes `&DeviceBuffer` and enqueues on a caller stream likely has the same cross-stream drop UAF. Worth one shared helper in a common crate.
2. **Buffer-context check (SEAM-02)** is likely missing in sibling wrappers too; a shared `ensure_same_ctx(buf, ctx)` would close it.
3. **`python/nv-py/src/compute.rs`** calls raw `cufftExecC2C/R2C/C2R` (lines ~425-456), `cublasSgemm_v2` (~188) and `curandGenerateUniform/Normal` (~573, ~649) directly with raw pointers, bypassing `Plan::ensure_workspace`, `set_stream`, `check_exec`, `validate_normal_params` (even-length rule) and the cuBLAS pointer-mode check. Owner of the Python slice should verify it re-implements those checks (it has `validate_dev_buf`, but the cuRAND even-length and cuFFT work-area rebinding need confirmation).
4. **`crates/nv-demo/src/fft_bloom.rs:412-445`** creates `Scratch::new(&cuda.default_stream())` then replaces it with `Scratch::new(stream)`; plans built earlier keep the old `ScratchInner`. Confirm every `exec_r2c/exec_c2r` there uses the same stream the plans' scratch was created on (FFT plan exec rejects mismatches at runtime, so a mismatch shows up as an error, not UB).
5. **`teardown` -> `record_err` read-and-clear (ERR-01)** semantics affect every crate using this pattern: the next unrelated call on the context reports the error. Other slices should check whether they rely on `bind_to_thread()` failing for unrelated reasons.
6. **cudnn `set_workspace`** (crates/cudnn/src/handle.rs, ops.rs) should be checked for the BL-01 lifetime pattern (raw workspace pointer bound to a handle without ownership).
7. FFT-03 and BL-05 depend on native documentation details that should be confirmed on hardware with a sanitizer run (`compute-sanitizer --tool memcheck`) when GPU tests are executed.
