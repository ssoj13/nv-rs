# Audit: media / IO slice (nvenc, nvdec, nvjpeg, nvofa, npp, nvcomp, cufile)

Date: 2026-11-23. Repo HEAD `38ec140`. Read-only audit; no cargo, no builds, no state-changing git.
cuda-core is an external git dependency (`cuda-rust` checkout `348895e`); its allocation/view semantics were
read from `~/.cargo/git/checkouts/cuda-rust-*/348895e/cuda-core/src` only to check seams.

Severity: P0 = UB / memory unsafety / crash / wrong results; P1 = leak, swallowed error, silent fallback,
significant perf; P2 = dedup/SSOT, dead code, doc drift.
Verdict: CONFIRMED = failing path traced in code; PLAUSIBLE = needs runtime/hardware or native-doc confirmation.

## 5) Risks / open seam questions for other slices

1. **cuda-core access leases vs raw-pointer FFI (X-1).** Is there a supported cuda-core API for registering an external async access, such as a lease or `record_access(stream)`? If so, every wrapper in this slice (and likely cublas/cufft/optix) should use it. If not, the workspace needs a documented "buffer must outlive stream completion" contract. The owner is the cuda-core slice.
2. **Context binding policy.** The slice is inconsistent: some constructors and drops bind the CUDA context and others do not (ENC-6, JPG-5, OFA-4). The workspace needs one rule, for example "every FFI entry point and every Drop binds". Check the optix, cublas and cudnn slices for the same split.
3. **Teardown error fidelity.** Every crate maps library-specific teardown codes to `CUDA_ERROR_UNKNOWN` through `Context::record_err`. A typed error sink in cuda-core (or tracing) would fix this workspace-wide.
4. **Stream ordering between "work stream" and "readback stream"** (DEC-4, OFA-2). The same pattern may exist in `nv-wgpu` interop and the `nv-demo` capture paths. Check whether cuda-core `default_stream()` is the legacy NULL stream or a non-blocking stream, because that determines whether these races manifest.
5. **NVENC B-frames (ENC-1, ENC-2).** `nv-demo` hard-codes `frameIntervalP = 1` (`gpu_export.rs:1051`). Any future quality preset that enables B-frames will break the MP4 export unless ENC-1 is fixed first.
6. **NVDEC crop (DEC-2).** Any slice that consumes nvdec output at 1080p (python bindings, demo playback) will see resampled rather than cropped frames.
7. **nvJPEG native contract (JPG-3)** and **Bitcomp header trust (CMP-4)** need confirmation against the CUDA 12.x/13.x nvJPEG and nvCOMP 5/6 docs, or a sanitizer run (`compute-sanitizer --tool memcheck`) on hardware.
8. **cufile on Linux.** None of the GDS paths (CUF-2, CUF-5) can execute on this Windows host. A Linux GDS runner should run the `#[ignore]` tests together with a fault-injection test that makes event record fail.
9. **Dead `Budget` / `Unsupported` variants** exist in nvenc, nvdec, nvofa and nvcomp. Check sibling wrapper crates (cufft, curand and others) for the same copy-pasted error enum.
