# `nv-demo` Agent Guide

## What & Why
`crates/nv-demo/` is the flagship interactive RTX showcase binary (`nv-demo`) of `nv-rs` (`188` unit tests + 7 ignored GPU / NVRTC / scene-census tests, counted on 2026-11-24; camera navigation is the external `camera-rs` crate and its tests run there). It exercises OptiX 9 hardware ray tracing (RT Cores), OptiX AI Denoiser & NGX DLSS SR/RR (Tensor Cores), cuFFT 2D diffraction bloom + CUDA tonemapping + zero-churn IAS/traffic/crowd streaming (CUDA Compute SMs), nvJPEG/nvENC export, atomic SDG JSON ground-truth export, and NVML/CUPTI telemetry inside a decoupled **60 Hz paced** `egui` / `egui-dock` / `wgpu` studio UI. [plan1_nvdemo.md](../../audit/2026-11-23/plan1_nvdemo.md) (acceleration roadmap) is closed; the open findings and their execution status are in [plan2_full.md](../../audit/2026-11-23/plan2_full.md) (Wave 3) and [PLAN.md](../../PLAN.md).

## Callers & Dependencies
- **Callers**: standalone desktop binary (`cargo run -p nv-demo --release`).
- **Workspace crates**: `optix`, `nv-wgpu`, `nv-loader`, `nvrtc`, `nvml`, `cufft`, `nvjpeg`, `nvenc`, `cupti`, `ngx`, `cuda-core-ext`.
- **External CG crates**: `cuda-core`, `cuda-bindings`, `appbus`, `camera` (`camera-rs`, features `egui` + `serde`; flight feel opted in via `CameraDriver::set_nav_extras` in `main.rs`), `csg-core`, `csg-actors`, `csg-scene` (`wgpu`), `csg-device`, `csg-scenes` (`csg-rs` `fa5e170`, 23 crates, 84-slot palette, 15-class `GasLedger` `246/256`), `egui`/`egui-wgpu`/`egui-winit`/`egui_dock`/`egui-phosphor`, `wgpu`, `glam`, `bytemuck`, `serde`, `serde_json`.

## How It Works
```text
winit + 60 Hz paced egui UI (main.rs: PresentMode::Fifo + WaitUntil 16.667 ms, ui.rs)
  |-- appbus::AppBus (StateSlot<RenderStateSnapshot>, UiCommand, RenderControl, RenderEvent)
  v
Async OptiX Render Worker (renderer.rs, rig.stream, live optix::LogFn)
  1. GpuPassProfiler::begin_frame (3-slot CUevent ring, non-stalling cuEventQuery)
  2. CsgGpuHost::step_dynamic (TrafficStateSoA + SceneBuilt::crowd, Freeze Pose zero-motion snap)
  3. CsgGpuHost::sync -> TrafficOnly (dual pinned 2 MiB DMA, growing to 16 MiB + uncompacted Accel::instances_into UPDATE)
                       | FullRepack (persistent GrowDeviceBuffer + InstanceBuffer + in-place IAS BUILD)
  4. Uninterrupted GPU stream burst (ONE end-of-frame fence):
     [IAS/Traffic/Crowd] -> [OptiX RT (SBT records 0..13, 680 B Params)] -> [OptiX Denoiser] -> [cuFFT Bloom] -> [Tonemap / HDR / DLSS-RR Pack]
  5. Single rig.stream.synchronize() -> GpuPassProfiler::poll_completed() -> FrameReady -> wgpu/DLSS/egui
```
- `src/csg_scene_host.rs`: 100% scene-agnostic `csg-scenes` host owning `Option<SceneBuilt>` (`Gundo`, `GundoOSM`, `Marina del Rey`, `SF House of AI`, **110-variant** `Inspector` incl. variant `109` 4-Archetype Crowd Showcase: Urban Human, `RoadSignStickman`, `QuadrupedDog`, 5-finger `SdgMannequin`), per-compound GAS cache, split CSG hit groups at `CSG_SBT_OFFSET = 8` (`hit_csg`, +1 shadow) / `CSG_SBT_PRIM_OFFSET = 10` (`hit_csg_prim`, +1 shadow, 11-GAS actor bank) routing, persistent `GrowDeviceBuffer<T>` pools (incl. `prev_xforms_buf` for `Motion` AOV), dual `2 MiB` (grow-on-demand to `16 MiB`) pinned `cuMemAllocHost_v2` staging buffers (`pinned_staging` + `pinned_prev_staging`), and atomic `export_sdg_json` via `csg_actors::extract_sdg_frame` + `CsgRayOccluder`.
- `src/optix_sdk.rs`: the one OptiX SDK discovery (`include_dir`): `OPTIX_ROOT/include` when `OPTIX_ROOT` is set (an `OPTIX_ROOT` without `optix.h` is an error, never a fallback), else the `%ProgramData%/NVIDIA Corporation/OptiX SDK*` install with the highest `OPTIX_VERSION`. `build.rs` includes it with `#[path]` (nvcc embedded PTX) and `renderer.rs::optix_headers` calls it for the NVRTC fallback and shader hot reload, so both compile against the same headers.
- `src/profiler.rs`: lock-free fixed-capacity `[f32; 120]` `RingBuffer`s (`FrameTimings`), non-stalling 3-slot `GpuPassProfiler` (`cuEventQuery` only, never `cuEventSynchronize`) reporting **RT Cores (OptiX)**, **Tensor Cores (Denoiser / DLSS)**, and **CUDA Compute (IAS / cuFFT / Tonemap)** ms, plus NVML/CUPTI/NGX probing.
- `src/viewport_toolbar.rs`: floating viewport toolbar, left-aligned on the `Top` / `Bottom` edges (`toolbar_anchor`), centred on `Left` / `Right`. The possession toolbar (`PossessToolbar`) is a second `ViewportToolbar` stacked on the inner side of the first (`ViewportToolbar::stack` + `stack_offset`: directly above a bottom-docked bar, below a top-docked one), same corner and alignment, edge follows the first. It is collapsed to its handle while not possessing; `possess_bar_expanded` expands it on entering possession unless the user collapsed it (`PossessBarPrefs::user_collapsed`) and collapses it on leaving unless pinned (`pinned`); both prefs persist in the `viewport_toolbar` section. Both bars share one frame and the design tokens `TB_BUTTON_SIZE` / `TB_ICON_SIZE` / `TB_COMBO_WIDTH` / `TB_SLIDER_WIDTH` / `TB_ITEM_SPACING` and `tb_icon_button` / `tb_separator`: every button is an `egui-phosphor` icon with its former text as tooltip (mounts are numbered `NUMBER_CIRCLE_*` icons, tooltip = mount label). Status badge / WGS84 pill clear bottom-docked bars via `bottom_reserve`.
- `src/wireframe.rs`: `DEMO:VIEWS` display modes (`DisplayMode::{Csg, Wireframe}`, persisted `DemoSettings::display_mode` / `wire_line_px`). Wireframe renders at the native viewport resolution (no DLSS input scale, no render scale; the first version rendered at the DLSS input size and was stretched, which looked pixelated). Raygen `aov_mode` `AOV_WIREFRAME = 11`: one pixel-centre primary ray, `(packed oct normal, object diameter, depth, instance key)` into `normal_f32`, 4 short AO rays into `color_f32.w`. `tonemap.cu`: `wire_classify` (lattice-edge classes + marching-squares crossings), 6 `wire_smooth` Laplacian passes (two-ring corner test; staircase error 0.455 -> 0.126 px), `wire_faces` (flat grey + AO, accumulated), `wire_emit` (the contour provider of the overlay, below). Voxel view is pending (csg-scene has no voxel / ESDF API yet).
- `src/overlay.rs` (+ `shaders/overlay_segment.cuh`, overlay section of `shaders/tonemap.cu`, `renderer::run_overlay`): the one generic overlay line renderer, GPU-first.
  ```text
  providers: OverlayProvider::emit(&OverlayCtx, &mut OverlayList)   (render thread, list reused)
     CPU primitives (small sets: rail, gizmos)          GPU sources (contours; later axes, bones,
     flatten(): project (pinhole) + cull -> records      csg-rs feature curves via LinesFramePlan)
        | one async upload from pinned staging                 | nv_overlay_push (atomic counter)
        v                                                      v
     ovl_segs[NvOverlaySegment; cap]   counter[appended, overflow, unprojectable, unsupported kind]
        -> ovl_splat: kind dispatch, world projection, scope filter (selected instance / radius),
           line LOD fade (proj_size_px vs min_screen_px), dashes, depth test vs primary depth,
           analytic constant-width coverage -> cov[px] = coverage << 24 | style (max wins)
        -> ovl_composite: history reprojected with the motion vectors, clamped to the 3x3
           coverage range, blended 0.25 new (TAA-style); linear-light blend into the tonemapped
           RGBA8 / scRGB targets (captures include it unless `in_captures` is off while recording)
  ```
  Under DLSS SR / RR (the display is the upscaled image) the raster runs at the output resolution: `renderer::OverlayOutPtrs` (main.rs `OverlayLayer`, one shared premultiplied linear RGBA16F buffer per frame index, allocated with the DLSS output size) receives the composite (`ovl_composite` `dst_ovl`), depth and motion stay at the render resolution and are read at the nearest texel (nearest, not bilinear: an interpolated depth at a silhouette belongs to no surface; DLSS outputs no depth), motion is scaled to output pixels; the RR wgpu tonemap and the SR `DlssSrComposite` fragment pass (DLSS output -> `DlssPass::display`) blend it after DLSS in linear light. The layer is cleared on frames that draw no overlay. Providers today: `ContourProvider` (wireframe contours) and `AxesProvider` (object axes: `ovl_axes` reads the device `csg_instances` / `csg_compounds` records, one thread per instance, no host copy; X red / Y green / Z blue, constant `axis_px` screen length (default 40, toolbar drag value), `SCREEN_CONSTANT_WIDTH`, depth mode `FadeHidden` from the style; skips invisible, mask-0 (compound without GAS), unbounded and `CROWD_BONE` instances; scope / radius filter, frustum and screen-size cull on the instance bounding sphere, plus a part-level LOD `OverlayFilter::axes_min_px` (default 96 px, toolbar `LOD` drag value): axes are per packed part until csg-rs P42 object grouping, so a part's triad needs its own projected size and fades in over `[axes_min, 3 axes_min]` (`overlay::axes_lod_px` mirror); selection members get `SELECTED` and their 12 oriented-box edges, class `NV_OVERLAY_CLASS_BOUNDS`). CPU mirror `overlay::axes_emit` (test-only) pins the kernel math. Skeletons slot: `SegmentClass::Bone` is reserved; the provider waits for csg-rs `ArchetypeSkeleton` (crowd bones are skipped by the axes on purpose). The Selected scope and the highlight read a device selection table (`OverlayRig::sel`, `MAX_SELECTED` = 64 keys, `GpuOverlayCamera::sel_count` / `scope_selected`); keys are primary-hit instance keys (`hit_instance_id`: CSG `user_id`, else `0xFF000000 | packed index`). Measured (`gundo` `road_cruise`, 1216x936, 4 spp, 6 bounces, DLSS-RR off, rail bench, 2 interleaved rounds x 600 frames, per-frame minimum): frame work median 99.38 ms overlay off -> 99.28 ms with axes on (tonemap section 0.032 -> 0.177 ms).
  Record contract: `OverlaySegmentPod` (64 B, Rust size/offset asserts) = `NvOverlaySegment` in `overlay_segment.cuh` (`static_assert`s), exported as `overlay::OVERLAY_SEGMENT_CUH`; interim until csg-scene publishes `OverlayCurvePod`. Faults are counted on the device, read back asynchronously (pinned staging, read the next frame after the fence) and reported as `OverlayFault` status lines. Shared filter `OverlayFilter` (persisted in `DemoSettings::overlay`, icon toggles in the viewport toolbar): master, kinds, scope (all / selected / radius), min screen px (cull + line LOD), temporal, in captures. No per-frame allocation; device buffers live in `OverlayRig`, created on first use and rebuilt on resize. Measured (`gundo` `grand_tour`, 1216x936, Wireframe, 2 rounds x 600 frames, per-frame minimum): tonemap section 0.60 -> 0.88 ms with the overlay, frame work median 4.97 -> 5.49 ms. Shimmer A/B (`--bench-rail grand_tour --png-dir`, 80 frames, far region): mean second temporal difference 9.08 -> 5.44 (LOD fade + temporal on vs off).
- `src/pick.rs` (+ `NvPickRecord` in `shaders/raytracer.cu`, `renderer::PickRig`): GPU picking. A click becomes `UiCommand::Pick(PickRequest)`; the next main launch carries the pixel (`LaunchParams::pick_px`) and the raygen thread of that pixel writes a 32 B record `{inst_id, part_id, t, world_pos, flags, frame}` from the primary ray it traces anyway (pick tap = sample 0, or the pixel-centre tap of AOV passes; misses and fisheye-masked pixels write a miss). The record is copied to pinned memory behind an event and consumed on the next frame by a non-blocking `cuEventQuery` (`PickState`: one pending request, newest click wins, one in flight, frame-tagged so a stale record is never consumed; a pending pick keeps a converged renderer launching). Click model shared with warpbro-rs / squarebob-rs (`sl_config::list::sel_mods`, modifiers latched at the press): click = select only the hit, Shift+click = toggle, empty space clears unless Shift, Escape does not clear; Ctrl+click / double click / Pick mode = possess. `Selection` (last key = active) lives on the render thread, feeds the overlay, is cleared on scene switch and reported by `RenderEvent::SelectionChanged` (status line). The host maps a key + hit point to the scene instance with a point lookup (`CsgGpuHost::resolve_pick`: containing visible instance whose `user_id` equals the key, smallest bounds first; crowd keys resolve to their actor; a mount-less part such as a wheel possesses its mounted body). The old host path (camera ray rebuilt on the host + CPU CSG march over every instance + CUDA crowd readback, `camera_projection_ray`, `CsgGpuHost::pick_possess`) is deleted. `PickedObject::osm` is a typed `None` until csg-rs P42 provenance.
- `src/is_counters.rs` (+ `nv_is_count` in `raytracer.cu`, `renderer::IsCounterRig`): per hit group IS invocations and traced rays for the csg-rs P37 A/B (see Benchmark).
- `src/semantic_filter.rs` (+ `nv_sem_hidden` / `nv_csg_trace_visible` in `raytracer.cu`): the viewport category filter (toolbar eye dropdown, sl-studio visibility-popover pattern with `sl_config::icons::tool_toggle` rows, All / None, per-id sub-rows, badge with the hidden count). `DemoSettings::hidden_semantics` (u64, persisted, resets accumulation) reaches the device as `LaunchParams::hidden_semantics`; every CSG intersection program resolves the hit class with csg-device `csg_instance_semantic` and rejects hidden ones (RPN re-traces past a hidden part up to 8 times; shadow programs take the radiance intersector while the mask is non-zero), so a hidden class vanishes from camera, bounce and shadow rays, per part. Mask 0 = one uniform branch per program. **Fast path** (`FILTER:FAST`): per instance an effective semantic mask M (`instance_semantic_mask`, the single source; P41 replaces its body) is classified against H (`classify`): fully hidden instances keep only visibility bit `0x80` (`LINES_OCCLUDER_MASK`; every render ray traces with `NV_RENDER_RAY_MASK` = `0x7F`), unaffected ones have their bit clear in the device bitset `LaunchParams::csg_sem_partial` (`nv_filter_partial`: the intersection program skips the reject test), partial ones keep the per-hit reject. `CsgGpuHost::apply_semantic_filter` refills the bitset only when H or the packed instances change (pointer 0 = every slot partial, used when no slot is unaffected); an H change re-emits the IAS instances as one `UPDATE`. Until csg-rs P41 M is exact only for semantic overrides (actors); crowd bones and all other instances are unknown (always partial). Classic instances carry the same rule on the host (`classic_instance_flags` through `classify`; floor GROUND, showcase objects UNKNOWN), so they are hidden in hardware. Cost with a non-zero mask is real (shadow programs evaluate the radiance intersector, RPN re-traces): interactive `gundo` Vista Del Mar with Vehicles + Industrial hidden went from about 135 to 226 ms RT; with the mask 0 only the uniform branch remains. Groups are one data table (`GROUPS`); Vegetation / Terrain features rows wait for csg-rs P41 ids, the OSM class section for P42 provenance (both shown disabled with that status).
- `src/ui.rs`: narrow-dock-safe `dock_scroll` + adaptive `prop_row_widths`/`slider_control_widths` + truncated `equal_grid`/`ComboBox` layout, Apple Maps clickable WGS84 HUD pill, live 4-way `Road Mode` (`3D | C1 | Hybrid | F-Rep`), `Freeze Pose` & `Save SDG JSON` controls, `EnginePhase` / `FROZEN` status badges, master `Fractal` enable toggle, Hero Fractal full TRS (`T * R_z * R_y * R_x * S`), and per-engine `Performance` sparklines.

## Optimizations & Invariants
- **Zero Per-Frame VRAM Alloc/Free Churn**: `optix::InstanceBuffer` (`d_optix_instances` + pinned staging, `256 KiB` initially, grown on demand up to `64 MiB`), uncompacted persistent `Accel::instances_into` (`compact: false`, `allow_update: true`, in-place `OPTIX_BUILD_OPERATION_UPDATE` on dynamic-only frames and in-place buffer reuse on full repacks), and persistent `GrowDeviceBuffer<T>` pools across all CSG library, instance, `prev_xforms`, and AABB buffers yield `0 cuMemAlloc`, `0 cuMemFree`, and `0 Vec` allocs in steady state.
- **Bounded GPU Waits**: the UI thread never blocks on an unbounded wgpu wait: still/window/video copies poll one submission index with `GPU_COPY_WAIT_TIMEOUT` (2 s, `main.rs`) and drop the capture with a status line on timeout or error. Native teardown failures recorded by `Drop` impls (`cuda_core_ext::teardown`) are drained and printed to stderr once at process exit (`teardown_report`, `main.rs`). CUDA stream/event waits cannot time out; they stay single end-of-frame fences.
- **Single End-of-Frame Fence**: zero mid-frame `stream.synchronize()` or `cuEventSynchronize()` stalls between RT, Denoiser, cuFFT Bloom, and Tonemap; double-buffered `free_bufs` overlaps Frame `N+1` CUDA/OptiX with Frame `N` Vulkan DLSS/UI presentation.
- **Strict 680-Byte C ABI**: `LaunchParams` (`renderer.rs`) and `Params` (`shaders/raytracer.cu`) are locked by compile-time `assert!` and `static_assert(sizeof(Params) == 680)` + `pick_px` at `428` (the former pad word) + `pick_record` / `is_counters` / `hidden_semantics` / `csg_sem_partial` at `648` / `656` / `664` / `672` + `__builtin_offsetof(Params, csg_prev_xforms) == 592` + `sdg_ray_count` at offset `632` + `classic_motion_count` / `classic_motion` at `636` / `640` + crossfade source sky block `env_from_lo` / `env_from_hi` at `192` / `384`, with `0` `double` tokens in `raytracer.cu`, true per-instance object optical flow (`csg_prev_xforms` + exact 3x3 affine inverse `csg_inv_xform_pt`), deterministic 4x RGSS AA zero-jitter AOV passes, and semantic IDs `0..19` (`18 = PEDESTRIAN`, `19 = ANIMAL`).
- **60 Hz UI Pacing & Safe Persistent IAS**: `main.rs` caps UI redraws to `60 Hz` (`PresentMode::Fifo` + `ControlFlow::WaitUntil(16.667 ms)` via `compute_next_ui_tick`); `ias_build_opts()` explicitly sets `compact: false` (`allow_update: true`) locked by `ias_build_opts_enables_update_and_disables_compaction`; `init_optix` installs a live `optix::LogFn` callback (`log_level = 3`, `NV_DEMO_OPTIX_LOG_LEVEL` override) with explicit `%LOCALAPPDATA%\NVIDIA\OptixCache` hint on `7999`.
- **Articulated Crowds & SDG Capture**: `CsgGpuHost` owns `SceneBuilt` directly, steps both `TrafficStateSoA`/legacy traffic (`!traffic.is_empty()`) and `SceneBuilt::crowd`, snaps `prev_xform = Some(inst.xform)` + `reset_crowd_motion_history()` + `traffic_dirty = true` on `Freeze Pose` `false -> true` transition for zero stale optical flow during clean multi-spp accumulation, and atomically exports `csg_actors::extract_sdg_frame` JSON keypoints/BBoxes (`Save SDG JSON` or auto-sidecar on frozen PNG/JPEG capture).
- **Large-Map Flight & Responsive UI**: progressive Shift ramp (`1x` <= 2s, `2^((t-2)/5)` up to `64x`), altitude-aware speed (`1x..=25x`), `RMB + Wheel` speed multiplier (`0.1..=64x`), and interactive fast-preview (`1 spp`, `<= 2` bounces + `150 ms` settle).
- **csg-rs `fa5e170` A/B (2026-11-24, same method, alternating main / adoption, 5 kept pairs)**: OptiX RT pass 44.11 -> 49.40 ms (+12 %), frame 45.31 -> 50.12 ms; cause not isolated (`audit/2026-11-23/csg_fa5e170_adoption.md`, `PERF:RT`).
- **Measured frame profile (2026-11-23, RTX 3080 Ti, default persisted scene `csg_mode = 1` with traffic, 2207x996, 4 spp, 6 bounces, denoiser / bloom / DLSS off; `perf_log.rs`, 5 runs x 600 frames)**: frame work 46-57 ms, of which the OptiX RT pass is 98 % (45.5-55.9 ms); host prep before the launch 0.74 ms, CUDA compute (IAS / crowd) 0.68 ms, tonemap 0.09 ms, crowd step 0.18 ms. Speed work must target the raygen / CSG shader (Nsight Compute), not host code. Reproduce with `NV_DEMO_PERF_CSV=<path>` (optional `NV_DEMO_PERF_FRAMES`, `NV_DEMO_PERF_WARMUP`); the CSV is written once and a status message names it.

## Benchmark (rail, deterministic)

Every RT timing and A/B uses the rail benchmark, never a free-running session:

```text
nv-demo --bench-rail road_cruise --scene gundo --out rail.csv [--frames N] [--warmup 60] [--image last.pfm]
```

- `bench.rs` parses the arguments (an unknown argument, a missing `--out`, or a rail id the scene does not have is an error and exit code 1; the error lists the scene's rail ids). `gundo` rails: `road_cruise` ("Street Navigation (24s)"), `landmark_slalom`, `urban_canyon`, `grand_tour`.
- The run forces Freeze Pose (traffic and crowd static), a free Pinhole camera, no demo animation and no time-of-day transition; it drops UI commands (stray clicks cannot possess or change the rail) and never writes `~/.nv-rs/nv-demo.json`. Everything else (resolution = viewport size, spp, bounces, sky, LOD) comes from the saved config, so restore the same config before each arm.
- The rail starts at time 0 and advances `time_scale / 60 s` per frame in lockstep with the renderer (the Smooth 60 FPS recording path, one rendered frame per step, damper snapped to the rail pose). Default `--frames` is one rail loop (`road_cruise`: 1440). Two runs of the same build render the identical eye sequence (checked on the CSV `eye_*` columns).
- The CSV (`perf_log.rs`, written via temp file + `sync_all` + rename) has the engine times plus `possessed, projection, eye_x/y/z, width, height, spp, bounces` per frame; reject a run whose state columns differ from the other arm. The process exits 0 after the CSV is written.
- `StartPerfLog` restarts the sample frame index at 0, so two runs of one build render bit-identical frames; `--image` writes the last measured frame's linear colour as PFM for a pixel A/B (compare max / mean abs diff and changed-pixel share).
- Foreign GPU load only adds time: with interleaved rounds, compare the per-frame minimum over rounds (frame i is the same work in every run) and report median / p95 of that.
- Flight stats (`flight_stats.rs`, collapsible subsection of "Cinema & Camera Rail"): while Auto-Drive flies, every `FrameReady` carries the frame's `PerfSample` (the same value the perf CSV records) plus `CsgStats` scene load (visible instances, LOD 0/1/2, culled, evaluation paths `[prim, union, exact union, RPN]`); the panel shows live speed / turn rate, RT min / median / p95 / max, a histogram, the five slowest rail positions (click = jump), RT vs rail time with the previous loop overlaid, visible instances and LOD 0 share vs rail time, and exports the frames in the bench CSV schema. Ring buffers are sized once; a new cassette, Auto-Drive start or Reset clears them. Not available (no source): height above ground (shows world `y`), rays / Mrays (no ray counter), visible crowd vs traffic split.
- **Fixed camera set + IS counters (csg-rs P37 A/B harness)**: `nv-demo --bench-views p37 --out views.csv [--frames 60] [--warmup 30] [--count-frames 4]`. Per view (`bench_views/p37.views`, or a file of `name scene viewpoint <id>` / `name scene eye x y z target x y z fov deg` lines) the run switches scene if needed, renders `warmup` frames, measures `frames` frames (RT ms from `GpuPassProfiler`, counters off), then renders `count_frames` frames with the IS counters on (counted frames are never timed) and writes one row: `view, scene, width, height, spp, bounces, eye, frames, rt_ms_median / min / p95, counted_frames`, then per counted frame `is_csg_rpn[_shadow], is_csg_prim[_shadow], is_union_part[_shadow], is_road_tile` (road / terrain tiles among the SBT-10 invocations; the RPN route is not split), `is_fractal, is_sphere, rays_radiance, rays_shadow, is_total`. Same freeze / camera rules as the rail bench; resolution and spp / bounces come from the saved config, so keep it fixed between the two arms of an A/B. Run it on the commit before and after each P37 wave and compare per view. The `p37` street / grazing placements come from the ignored census test `city_scene_semantic_census_and_viewpoints` (it prints semantic ids per scene, viewpoints and the road parts near them); re-check them when csg-rs moves roads. Interactive: Flight stats "IS counters (debug)" toggle (or `--is-counters`) shows the latest counted launch. Counters: one 64-bit atomic per event into 12 groups x 32 stripes; `LaunchParams::is_counters` is 0 unless counting (one uniform branch per call site when off). First run (2026-11-24, 832x640, 4 spp, 6 bounces): see `CHANGELOG.md`.
- `NV_DEMO_PERF_CSV` / `NV_DEMO_PERF_FRAMES` / `NV_DEMO_PERF_WARMUP` still log a free-running session; such numbers depend on camera state and traffic and are not A/B evidence.

## Traps & Future Improvements

- **csg-rs contracts (`fa5e170`, adopted 2026-11-24 in `9b6e178`)**: `SceneModule::build` returns `Result<SceneBuilt, SceneBuildError>`; the only production call (`CsgGpuHost::rebuild_scene`) maps it to the sync error that `renderer.rs` shows as `RenderEvent::StatusMessage` (never `expect`). The WGS84 HUD reads `SceneDescriptor::geo_origin` (`ui::active_geo_origin`); `None` (classic, `gundo`, `inspector`) shows no coordinates, never a fallback; world `y` is already absolute altitude. Union compounds go on the multi-AABB GAS (`compound_gas_plan`): `PURE_UNION` (disjoint parts) on SBT 10 (`__intersection__csg_prim`, per-primitive hit), `FIRST_HIT_UNION` (overlapping / touching parts, csg-rs `6e84ff6` P23) on its own SBT 12 group (`__intersection__csg_union_part[_shadow]` -> `csg_union_part_hit` / `_shadow`, which hide internal faces exactly); keep the groups separate, the exact rule costs ~193 registers vs ~142 and would tax the ~5,700 single-primitive instances of `gundo`. The Inspector crowd showcase index is `csg_scenes::ACTOR_SHOWCASE_VARIANT_IDX` (it moved from 109 to 111 when csg-rs added kits); never hard-code it. `SceneBuildConfig::smart_fill` stays at its default (off). The PTX cache key hashes `csg_device::CSG_EVAL_CUH`. The pipeline stack is sized from the linked programs (`renderer::size_pipeline_stack`, continuation 320 B, `css_is = 0`): the CSG span stack is per-thread local memory (`__local_depot`, 4240 B for the large RPN frame), not OptiX stack. Registry tests check scene-id containment and never hard-code scene, viewpoint or rail counts (csg-rs adds data-only scenes).
