Device-side Rust crates live in a separate Cargo workspace at `device/Cargo.toml`, outside the host workspace. They target PTX compilation via `cuda-oxide` (`cargo oxide`) using the toolchain pinned in `rust-toolchain.toml`, while the host workspace builds against the `cuda-rust` host crates.

The `device` workspace contains four members:

- `device/optix-device` — OptiX device API (`#![no_std]`) for Rust ray-tracing programs.
- `device/optix-device-macros` — proc-macro crate providing `direct_call!` and `continuation_call!` as inline PTX indirect calls.
- `device/cuda-tex-device` — bindless CUDA texture fetches and surface reads/writes (`#![no_std]`).
- `device/optix-device-tests` — GPU integration tests driving `optix-device` and `cuda-tex-device` programs through the host `optix` and `cuda-core-ext` crates.

## `optix-device`

`optix-device` provides both generated SDK bindings and a hand-written typed layer for OptiX programs (`__raygen__*`, `__miss__*`, `__closesthit__*`, etc., written with `cuda_device::kernel`):

- **`raw`** — one `unsafe fn` per `_optix_*` intrinsic of the installed OptiX SDK, generated at build time by `build.rs` using `nv_bindgen::device_asm::scan_optix` and `emit`. Each wrapper emits the exact inline PTX from the SDK's device headers (`optix_device_impl*.h`) via `cuda_device::ptx_asm!`. The build fails if any header intrinsic lacks a wrapper, and writes `optix_device_inventory.json` (`INVENTORY`).
- **`sys`** — `no_std` OptiX types and constants generated from `optix_types.h` via `nv_bindgen::core_types`.
- **Typed modules**: `state`, `payload` (`Payload`), `trace` (`trace`, `Ray`, `TraceOptions`), `coop_vec` (`CoopVec`), `exception`, `footprint`, `geometry`, `hitobject`, and `transform`, plus `direct_call!` and `continuation_call!` re-exported from `optix-device-macros`.

:::caution[64-bit pointers required]
Any crate whose OptiX programs use `optix-device` must disable short pointers (`CUDA_OXIDE_NO_SHORT_PTR = "1"` or `short-pointers = false` in `.cargo/cuda-oxide.toml`). `cuda-oxide`'s default `llc --nvptx-short-ptr` addresses `.local` memory through 32-bit registers, which causes OptiX to fault with `CUDA_ERROR_ILLEGAL_ADDRESS` when local memory is used (for example address-taken locals, runtime-indexed arrays, or `CoopVec` pointer paths for `N > 64`).
:::

## `cuda-tex-device`

`cuda-tex-device` (`#![no_std]`) implements the device half of CUDA's bindless textures and surfaces using `cuda_device::ptx_asm!`. Host handles come from `cuda_core_ext::TextureObject::handle` (`TexObject = u64`) and `cuda_core_ext::SurfaceObject::handle` (`SurfObject = u64`).

- **Texture fetches (`TexElem`)**: covers `tex1D` through `texCubemapLayeredGrad`, `tex1Dfetch`, `tex2Dgather` (`tld4.{r,g,b,a}.2d`), and sparse-residency `*_sparse` overloads returning `(value, bool)` via predicate + `selp.u16`. Generic over `f32`, `i32`, and `u32` (scalar, `[T; 2]`, or `[T; 4]`).
- **Surface reads and writes (`SurfElem`, `Boundary`)**: covers `surf*read` and `surf*write` (`suld.b.*` / `sust.b.*`) across `i8`/`u8`, `i16`/`u16`, `i32`/`u32`/`f32` (1, 2, or 4 components), and `i64`/`u64`/`f64` (1 or 2 components), with `Boundary::Trap` (default), `Boundary::Clamp`, and `Boundary::Zero`.

`src/cuda_tex_device.rs` is generated by `gen/gen.py` from its op table; edits belong in `gen/gen.py`, not in the generated source file.
